# Native frame interpolation worker

`node scripts/build-interpolation-sidecar.mjs` from `app/` builds the x64 native worker, verifies the default catalog model, performs actual non-midpoint CPU inference, and stages `.interpolation-bundle/current/interpolation-sidecar/`. CMake, Ninja, a C++17 compiler and tar are required on Linux. Windows uses Visual Studio 2022 or 2026 with the x64 C++ toolset and tar; the helper discovers CMake from PATH or the installed Visual Studio tools and selects the available default generator. Users of the portable application need the vendor/OS Vulkan driver, without Python, CUDA or a Vulkan SDK installation.

The Node helper exports `ensureInterpolationBundle()` and the layout module exports `getInterpolationSidecarDir()`. Native dependency archives are pinned by commit and SHA256. Build parallelism is limited to four jobs. Packaging includes those archives, the modified worker sources, source/model identities, hashes and all licenses. GPU support is runtime detected. No automatic CPU fallback occurs after a device or inference failure.

The stream always carries RGB channel order on Windows and Linux. Frames are normalized to float32 [0,1], padded with zeros at the right and bottom to multiples of 64, passed to the converted full RIFE graph as `in0`, `in1`, `in2` (alpha), and read from `out0`. The wrapper crops by row stride and rounds/clamps back to RGB8. Internal Vulkan FP16 storage is enabled, FP16 arithmetic disabled. CPU float32 remains available explicitly for qualification and diagnostics. The worker supports the exact 4.25/4.26 model pairs in `app/interpolation-models.json`; do not substitute models requiring different graph layouts or padding.

The Warp layer and shader/header generator under `vendor/rife/` derive from [k4yt3x/librife-ncnn-vulkan](https://github.com/k4yt3x/librife-ncnn-vulkan/tree/f1de3a97c49e1bed4a625aa8eef92586a4871e74), copyright nihui, MIT. Local changes add graph tensor checks, shader compilation/pipeline failure propagation, allocation checks and border clamping before float-to-int conversion. The worker bypasses the upstream filename-based image loader and large TTA wrapper. The modified sources and upstream MIT license are included in every bundle.

Models are exact converted bytes from [TNTwise/rife-ncnn-vulkan](https://github.com/TNTwise/rife-ncnn-vulkan/tree/13338e38debe2e400b3eeecf6792312d01a692f9/models). The original model author explicitly applies MIT to linked trained models in [Practical-RIFE](https://github.com/hzwer/Practical-RIFE/blob/bbfd2ea90910789a860ea3e2b32a240cd577b75e/README.md#trained-model); see `model-license.txt`. Catalog entries bind their converted origin, lengths and hashes. This build consumes the published conversions; it does not independently regenerate them from PyTorch. A conversion recipe is referenced by TNTwise's README, but reproducibility from the original checkpoint was not verified here. Do not describe this dependency build as a reproduced model conversion.

`protocol.md` defines the process interface. Run the native integration test with `VFL_TEST_RIFE_WORKER=/absolute/path/to/vfl-rife VFL_TEST_RIFE_MODEL=/absolute/model/directory node --test test/interpolationNative.test.mjs` after building. The tests exercise binary records, channel order, dimensions, fractional alpha, invalid input and redacted failures; they do not establish perceptual parity with other applications.

## Optional Torch backends

`app/optional-interpolation/` contains VFL's separate Python worker and adapters for GMFSS Fortuna (Union), GIMM-VFI-R-P and LDF-VFI. They do not use the RIFE ncnn graph. Their exact upstream source/weight/license allowlists are the adjacent `*-files.json` manifests. The desktop installer downloads these immutable files and the interpreter/wheels in `app/optional-interpolation-runtime.json`, assembles them offline in app-owned storage, verifies the installed inventory and runs a real model self-test before activation. End users do not run pip or install a system Python, CUDA toolkit or compiler. GIMM is noncommercial; preserve its upstream license files and UI marker.

The shared runtime targets Windows/Linux x64 and NVIDIA CUDA. LDF additionally uses compiled Triton FlexAttention and BF16. The Windows runtime includes app-local, unmodified Microsoft redistributable files with their terms; maintainers distributing those files must comply with the Visual Studio redistribution license. Optional downloads retain their own component licenses, including the CUDA runtime terms in the pinned wheels.

The optional pair worker uses the same float32-alpha/RGB8 record shape as the native worker. LDF instead consumes a bounded seekable raw RGB file and emits an autoregressive sequence for an integer factor. The desktop owns PTS scheduling, scene boundaries, source anchors, scratch limits, cancellation and final output publication. Every source import is preceded by manifest verification. Bundling copies the worker, adapters and manifests into `optional/` and retains their corresponding sources and runtime lock under `source/`.

For a maintainer runtime fetch/assembly, use `node scripts/optional-interpolation-runtime.mjs --help` from `app/`. This utility uses the same pinned artifacts and offline assembler as the desktop installer; it never runs package install hooks. Runtime/model inference requires a supported driver and sufficient GPU memory. Protocol checks are smoke tests and do not establish comparative visual quality.
